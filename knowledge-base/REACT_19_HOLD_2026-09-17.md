## TL;DR

Se intentó subir **React 18 → 19** (el PR #5 de Dependabot, el major más pesado).
El upgrade **compila y renderiza perfecto** (build verde, tipos 19 OK, preview
público limpio), **PERO** la doble auditoría §6 encontró un **bloqueante real,
documentado y NO verificable de forma desatendida**: **`@zoom/meetingsdk` (Component
View / embedded) NO es compatible con React 19** y correría bajo el React 19 del host

Por el **gate de seguridad ineludible** que fijó Pablo ("mergear SOLO si TODO está
impecable Y verificable · CERO incompatibilidad de librerías detectada · ante
CUALQUIER duda de compat o algo no 100% verificable → NO mergear, dejar en la rama"),
**se resolvió HOLD.** Romper prod desatendido para ~100 usuarios es peor que diferir.

**`main`/prod quedó 100% intacto** (`f7330cd`, React 18) — no hubo merge, no hace
falta revert.

## El bloqueante (corrige una premisa que yo tenía mal)

**Premisa previa (equivocada):** "Zoom bundlea su propia React 18 aislada del host,
así que React 19 en el host no lo afecta."

**Realidad (probada por el agente de compat):** el build **`@zoom/meetingsdk/embedded`**
(Component View — el que usa el campus) **externaliza React al host**. Cabecera UMD de
`node_modules/@zoom/meetingsdk/dist/zoomus-websdk-embedded.umd.min.js`:

```js
module.exports = t(require("react"), require("react-dom/client"), require("react-dom"))
```

- `@zoom/meetingsdk` tiene `dependencies: {}` (React sólo como **peer** exacto `18.2.0`)
  y **no hay copia de react anidada** → `require("react")` resuelve al **host React
  19.3.0**.
- El `dist/lib/vendor/react.min.js` (18.2.0) que trae el paquete es para el **Client
  View / build global** (`window.React`), **NO** para el embedded.
- El bundle usa **`findDOMNode` (14×)** y **`childContextTypes` (1×)** — **ambos
  REMOVIDOS en React 19**.
- **Zoom lo documenta como incompatible, sin versión con fix** (a mar-2026):
  *"React 19 not supported with embedded SDK"* — error típico
  `Cannot read properties of undefined (reading 'ReactCurrentOwner')`.
  - https://devforum.zoom.us/t/react-19-not-supported-with-embedded-sdk/134827
  - https://devforum.zoom.us/t/meeting-sdk-not-loading-the-meeting-with-react-19/127507
  - https://github.com/facebook/react/issues/28926 (removal of `findDOMNode`)

**Por qué NO es verificable desatendido:** el fallo dispara en `client.init()` /
`client.join()` **cuando un alumno entra a una clase Zoom en vivo** — NO en boot, NO
en build, NO en un smoke de BD. Es exactamente el patrón que ya nos mordió (regla R18 /
E-GG-42): build limpio + SELECT verde, y rompe en producción cuando un usuario real
dispara el flujo. Sin una reunión Zoom real no se puede descartar.

**Superficie afectada:** `src/modules/campus/components/ZoomLiveEmbed.tsx`,
`ZoomCustomVideoStage.tsx`, montados desde `EncuentrosEnVivoAlumno.tsx:176`. Zoom es el
canal **primario** de clases en vivo (E-GG-145; `plataforma` por encuentro, default Zoom).

### Riesgo secundario (mismo mecanismo)

**`@webex/widgets` 1.28.2** — peer `react/react-dom 18.3.1` exacto, su ESM importa el
React del host (montado con `createRoot` del host en `WebexLiveEmbed.tsx:95-107`),
bundle con `findDOMNode` (15×) + `defaultProps` (116×). Proveedor **secundario**
(`plataforma='webex'`), pero rompería igual bajo React 19. Tampoco verificable sin una
reunión Webex real.

### Resto de librerías: OK

`react-router-dom` 7.18.3 (peer `>=18`, soporte oficial 19), `@tiptap/react` 2.27.2
(peer incluye `^19`), `lucide-react` 1.47 (peer `^19`), `react-easy-crop` 5 (peer laxo).
supabase-js / exceljs / jspdf / html2canvas / papaparse / etc. no dependen de React.
No hay radix / headlessui / cmdk / framer-motion / sonner / recharts.

## Decisión: HOLD (aplicación del gate)

El gate de Pablo (verbatim): *"mergear a main/prod SOLO SI todo está impecable: build
verde + §6 sin bloqueantes + render/preview limpio + CERO incompatibilidad de
librerías detectada. Si hay CUALQUIER duda, warning de peer/compat, o algo no 100%
verificable en preview → NO mergear... NUNCA forzar. Romper prod desatendido para 100
usuarios es peor que diferir."*

Se cumplen 3 de las 4 condiciones (build verde ✅, §6 código/runtime sin bloqueantes ✅,
preview limpio ✅) pero **FALLA la 4ª de forma inequívoca**: hay **incompatibilidad de
librería DETECTADA y documentada** (`@zoom/meetingsdk`), sobre una **superficie viva y
primaria**, **NO verificable de forma desatendida**. → **HOLD.**

**Estado físico:** `main` = `origin/main` = `f7330cd` (React 18, intacto). El diff
`main..fix/react-19` es SÓLO `package.json` + `package-lock.json` (cero código fuente).
No hay nada que revertir.

## Cómo retomar esto cuando haya tiempo/decisión de Pablo

React 19 está **listo a nivel de app** (código/tipos/runtime limpios). El único
trabajo pendiente es **desacoplar los 2 widgets de video** del React del host. Opciones,
de menor a mayor esfuerzo:

1. **Esperar** a que Zoom publique soporte oficial de React 19 para el embedded SDK
   (y Webex para sus widgets). Cuando salga: bump del SDK + verificar en una clase real.
2. **Aislar cada widget en su propio React 18** — p. ej. cargar el **Zoom Client View
   por CDN** (con su `window.React` 18 propio) en vez del embedded que toma el host; el
   widget corre en su árbol aislado. Requiere reescribir `ZoomLiveEmbed`/`WebexLiveEmbed`
   y **probar con una reunión real** (Zoom y Webex) antes de mergear.
3. **Congelar** esos módulos (feature-flag las clases en vivo) mientras se sube el resto
   a React 19. No recomendado: las clases en vivo son core del campus.

**Requisito de cierre en cualquier caso:** la validación NO puede ser sólo build+preview
— hay que **entrar a una clase Zoom (y Webex) en vivo** y confirmar `join()` + video +
registro de asistencia. Sin eso, el merge sigue vedado por R18.

**Higiene menor detectada (no bloqueante):** el comentario de `.npmrc`
(`legacy-peer-deps=true`) quedó **stale** ("nosotros estamos en 18.3.1"); ese flag
**enmascara** el conflicto de peers 18↔19 en `npm install` (no falla, no avisa). Si se
retoma react-19, actualizar/eliminar ese comentario y re-evaluar si el flag sigue siendo
necesario.
